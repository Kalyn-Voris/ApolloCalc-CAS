# C/128KB — C99 增强版

- **状态**：**已完成（冻结）**——v1.0.0（2026-10-13）首发，v1.1.0（2026-10-21）
  零堆内存重构后逐字节冻结
- **组件版本**：v1.1.0（本目录 `VERSION`；覆盖本目录的最后一个全局 Tag 亦为
  v1.1.0，冻结后不再递进，沿革见根 [CHANGELOG](../CHANGELOG.md)）
- **堆限制**：128KB（全部静态分配，`.bss` 段，禁止 malloc/free）
- **目标平台**：Cortex-M7 / ESP32-S3 级别 MCU，或任何有 128KB 以上 RAM 的嵌入式 Linux
- **编译门禁**：`-std=c99 -Wall -Wextra -Wstrict-prototypes -Werror -O2`（零警告）

## 功能对等承诺（已兑现）

与 [JS/128KB](js-128kb.md) 逐功能对等：五分量精确形式、12 元线性方程组、扩展数学函数集
（双曲/反双曲/复数域）、数值微积分与泰勒展开、有理根检验与低次因式分解、加倍的表达式池
与 preCheck 阈值。`tests/` 下的共享 JSON 用例已通过跨版本冒烟比对给出与 JS 版一致的结果
（见"跨版本一致性"，50/50 用例一致）。

在 JS 128KB 之外追加四个 C 独有层：大整数（第 6 轮）、矩阵（第 7 轮）、特殊函数（第 8 轮）、
符号求导 + 因式分解（第 10 轮）。

## 与 C 64KB / JS 128KB 的差异

**相对 C 64KB 的增量**：

1. 精确形式三分量 → **五分量**（`(a + b√c)/d × 10^e`，支持混合形式与科学计数法）
2. 新增双曲 / 反双曲函数（sinh/cosh/tanh + asinh/acosh/atanh）
3. 新增复数域扩展函数（cExp / cLn / cPowReal）
4. 新增数值微积分（一阶/二阶导数、定积分、极限）与泰勒展开（≤16 阶）
5. 新增有理根检验与显式栈降次；三次/四次整数与分数根获得精确形式
6. 线性方程组 6 元 → **12 元**（矩阵池 42 → 156，根池 6 → 12 槽）
7. 表达式池全部翻倍：token 512 / 数值 256 / 求值栈 128 / RPN 512 / 运算符栈 128
8. preCheck 阈值翻倍：深度 ≤ 6 / 函数 ≤ 4 / 变量 ≤ 10
9. 水位门禁 48KB → **96KB**
10. 新增四大 C 独有模块：`ac_bigint` / `ac_matrix` / `ac_special` / `ac_symbolic`

**相对 JS 128KB 的对等性**：JS 128KB 的全部功能均已实现（见上表），数值输出经 50 例跨版本
冒烟比对一致。C 侧额外提供四个 JS 无对应实现的模块。唯一接口差异见下节。

## 依赖关系

```
第 1 轮  ac_exact（五分量）────┬──→ 第 10 轮 ac_symbolic（因式分解取五分量）
                              │
第 5 轮  ac_ratroot ──────────┴──→ 第 10 轮 ac_symbolic（有理根降次）
第 3 轮  ac_calculus ─────────────→ 第 5 轮 ac_solve_newton（牛顿法）
第 6 轮  ac_bigint ─── 独立（ac_util 的定点数↔大整数互转依赖它）
第 7 轮  ac_matrix ─── 独立
第 8 轮  ac_special ── 独立（复用 ac_math 基础函数）
```

- 第 10 轮符号模块依赖**第 1 轮五分量**（有理根 → 精确形式规范化）与**第 5 轮 ratroot**
  （`ac_rat_root_descent` 降次）；因式分解会改写 `ac_solvers` 的 `g_coeffs`（降次提交副作用）。
- 第 5 轮牛顿法依赖**第 3 轮 calculus** 的求值/导数基础。
- 第 6 轮 bigint 独立，但 `ac_util` 的 `fx_from_bigint` / `fx_to_bigint` 反向依赖它。
- 拼接顺序（Makefile `SRC`）：parser → evaluator → exact → solvers → ratroot → math →
  complex → calculus → numtheory → base → bigint → matrix → special → symbolic → util。

## 已知接口差异

- `guardMultivariateNonlinear` 在 JS 64KB / JS 128KB 中定义了但未被任何求解流水线调用
  （死代码，仅测试里以"单变量解析器：恒通过"调用）。C 侧不提供该函数。

## 跨版本一致性

- **C128 vs JS128**：`tests/bench/c128-smoke.csv` vs `js128-smoke.csv`，
  50 例全部一致（根数 100% 一致、数值 100% < 1e-9、五分量精确形式逐字段精确相等），
  见 [tests/bench/SMOKE-DIFF-128.md](../tests/bench/SMOKE-DIFF-128.md)
- 用例覆盖：多项式求解 30 例（二次/三次/四次/五次门禁）+ 线性方程组 4 例 + preCheck 门禁 3 例
  + 五分量精确形式 13 例
- **v1.0.0 跨版本对拍**：`git archive HEAD` 解出 v1.0.0 快照，各自构建 `smoke_runner`
  并输出 53 行 CSV，`diff` **逐位一致（输出为空）**。内存重构未改变任何可观测行为
- 复现：`mingw32-make smoke_runner && ./smoke_runner.exe > ../../tests/bench/c128-smoke.csv`，
  再跑 `node ../../tests/bench/diff-smoke128.js`
- 已知良性差异：C `pow()` vs JS 内建、libm vs V8 —— 仅末位 ulp（原始 CSV 文本有 3 处
  最末位数字不同，数值差为 0，远小于 1e-9 容差）
